登入需要 PostgreSQL。沒有資料庫時，畫面與多數測試仍可執行，但建立營運者會失敗。

```bash
docker compose up -d postgres
pnpm db:migrate
pnpm dev
```

打開 http://127.0.0.1:5180 。若還沒有營運者，會進到初次設定。

## 初次設定與登入

初次設定只會成功一次。它建立第一位營運者，並寫入工作階段 Cookie `s4n_session`。

- 密碼以 Argon2id 儲存（記憶體 19 MiB、時間成本 2、平行度 1），資料庫裡沒有明文
- Cookie 是 `httpOnly`、`SameSite=Lax`。`S4N_ENV=production` 才加上 `Secure`，本機 HTTP 不加
- Cookie 的值只是伺服器上的工作階段編號。約 12 小時後到期，使用一段時間後會換成新編號，舊的立即失效
- 登出會刪掉伺服器上的那一筆
- 登入失敗太多次會先被擋下。這個計數在單一程序的記憶體裡，多個 API 實例不會共用

會改動狀態的儀表板請求仍要通過來源允許清單。本機會同時接受 `localhost` 與 `127.0.0.1`。開發時儀表板把 `/api` 轉到 API，瀏覽器看起來是同一個來源。

贊助頁的「建立贊助」不需要登入。付款回呼也不看這個 Cookie。

## 外掛

外掛庫列出已安裝外掛的 `s4n-plugin.json`。每個外掛可以啟用或停用。預設是停用。

設定表單依 manifest 的 `settingsSchema` 產生。標了 `x-s4n-secret: true` 的欄位只會顯示「已設定」或「尚未設定」。儲存之後，API 不會回明文，也不會回密文。留空表示不改掉已經存好的密文。

`payments.provider`、`secrets`、`network` 只給明確列在官方允許清單上的外掛。名字以 `official.` 開頭並不夠。

## 帳本與測試贊助

帳本頁讀取核心訂單：待付款、已付款、未成功。時間以台北時間顯示。付款方式只顯示綠界或歐付寶，不顯示金鑰。

工作台上的「送出測試贊助」會發出 `s4n.donation.test`。它會標成測試，寫進事件紀錄，不會寫進帳本，也不會變成已付款的贊助。工作台下方的「事件紀錄」看得到這一筆。

待付款的那一列可以「向金流查詢」。這會用伺服器上的金鑰向廠商查單，金額仍以帳本為準。

## 把贊助提醒加進 OBS

1. 在外掛庫啟用「贊助提醒」。
2. 打開「疊層」，產生網址。網址裡的 token 就是通行權杖。
3. OBS 新增瀏覽器來源，貼上該網址。建議寬度 1280、高度 720，或與預覽畫布相同的寬高，並勾選透明背景。
4. 不要加上 `preview=1`。直接打開網址時，那個參數只鋪棋盤。OBS 請用沒有這個參數的網址。
5. 在疊層頁的預覽，或回到工作台，送出測試贊助。疊層會顯示名稱、新台幣金額與留言。名稱和留言只當文字畫出來，不會變成 HTML。

疊層頁網址的下方可以預覽 OBS 畫面。預覽載入與 OBS 相同的疊層，並按畫布比例縮小，位置與 OBS 一致。預設是 1920×1080，也可以選 1280×720、直式 1080×1920，或填入瀏覽器來源的寬度與高度。

背景可換成深色棋盤、淺色棋盤、純綠，或一張遊戲畫面。範例畫面與上傳的圖片只留在這個瀏覽器，不會送到伺服器。透明的地方會露出背景。

預覽裡的測試贊助與工作台同一條路徑，不會寫進帳本。若同時啟用多個疊層外掛，可以逐個預覽，或全部疊加，接近 OBS 把多個瀏覽器來源放在同一塊畫布上。重新產生網址後，預覽會改用新權杖。預覽用受限的 iframe 載入疊層，並設定不送出 Referer。權杖仍只放在疊層網址裡，跟貼進 OBS 的那條相同。

## 把 Twitch 聊天加進 OBS

聊天分成兩個官方外掛。`official.twitch-chat` 是來源，只負責連到 Twitch。`official.chat-overlay` 是顯示，只吃已經正規化的聊天事件。之後若加上 YouTube，換的是另一個來源外掛，這塊疊層不用改。

1. 在外掛庫啟用「Twitch 聊天」與「聊天疊層」。
2. 打開 Twitch 聊天的設定，填頻道名稱（登入名稱，不含 `#`）。不填 Client ID 也能連線：伺服器使用匿名的 `justinfan` 與公開的 `SCHMOOPIIE`，那不是你的 Twitch 權杖。
3. 若要頻道與全域徽章圖，再填 Twitch Client ID 與 Client Secret。這兩欄是密文，畫面只顯示「已設定」或「未設定」。它們用 `S4N_MASTER_KEY` 做 AES-256-GCM，不會出現在 OBS 網址。
4. 聊天疊層可以調訊息停留秒數（0 表示一直留著）、最多行數、隱藏機器人、隱藏以 `!` 開頭的指令、關鍵字遮罩（換成同樣長度的 ＊），以及是否同步刪除與封鎖。預設會隱藏 Nightbot、StreamElements、Moobot、Streamlabs、Fossabot。
5. 「把贊助混進聊天」預設關閉。打開之後，已入帳的贊助與測試贊助會多一行在聊天裡。測試贊助（`s4n.donation.test`）仍然不寫入帳本。
6. 打開「疊層」。贊助提醒與聊天疊層是兩條網址，共用同一組權杖，`plugin` 參數不同。把聊天那條貼進 OBS 的瀏覽器來源，勾選透明背景。不要加 `preview=1`，也不要把 Twitch 的任何權杖貼進網址。
7. 預覽面板的「送出測試聊天訊息」會送一則帶徽章與 Kappa 表情的訊息，不需要開著實況。若要同時看到贊助樣式，打開混入贊助後再送測試贊助。

刪除訊息（CLEARMSG）與封鎖、超時、清空（CLEARCHAT）會從疊層拿掉對應的行。伺服器會重連、回應 Twitch 的 PING 與 RECONNECT，並限制單則文字長度與每秒則數。畫面上的名稱、內文與徽章標題都是文字，不會被當成 HTML。

徽章圖放在 API 程序的記憶體裡，連同一起的還有向 Twitch 換到的短暫應用程式權杖。重啟之後，圖還沒回來時疊層改畫文字標題。這個快取不進資料庫，也不進事件紀錄。詳見 [事件紀錄](/guides/events/)。

重新產生網址會使舊權杖失效。請不要把網址貼到公開的地方；它不使用登入 Cookie。疊層頁面會拿掉網址列裡的 token，並要求瀏覽器不要送出 Referer。

目標、跑馬燈與語音仍是佔位，沒有自己的畫面。疊層只會收到已啟用外掛對應的事件。贊助提醒停用時，測試贊助不會出現在畫面上。

事件寫在 PostgreSQL，重啟 API 或 OBS 斷線後可以依序號補上。規則、保留期限與升級步驟見 [事件紀錄](/guides/events/)。登入失敗的計數仍在單一程序的記憶體裡。帳號、工作階段、外掛設定與疊層權杖留在資料庫。
